# Content Creation Templates

## Family Boundary

- Recognition signal: 受众、主题、提纲、文案、演讲、发布或内容排期。
- Expected output: 形成可继续编辑、制作或发布的内容资产。
- Routing rule: 以材料要完成的工作为准，不按单个关键词分类；会议产出的独立规格文档只有在用户明确要求时才切换家族。

## Subtypes

### announcement

- Classification signal: 公告相关素材，且主要任务与标题一致。
- Expected output: 公告；形成可继续编辑、制作或发布的内容资产。
- Required information: 影响对象、变更内容、用户影响、生效时间、需要的行动、支持路径、例外/回滚。
- Recommended components: `ComparisonMatrix`（比较文案版本）、`Quote`（保存事实性证明）、`Checklist`（检查准确性和发布条件）。
- Example: [公告](../template-examples/content-creation/announcement.mdx)

### article-draft

- Classification signal: 文章草稿相关素材，且主要任务与标题一致。
- Expected output: 文章草稿；形成可继续编辑、制作或发布的内容资产。
- Required information: 受众问题、读者承诺、中心主张、证据地图、关键论点、反对意见、发布渠道、最终事实检查。
- Recommended components: `Toc`（稳定文章论证结构）、`InsightCard`（保留中心判断）、`Checklist`（检查来源和发布条件）。
- Example: [文章草稿](../template-examples/content-creation/article-draft.mdx)

### interview-record

- Classification signal: 采访记录相关素材，且主要任务与标题一致。
- Expected output: 采访记录；形成可继续编辑、制作或发布的内容资产。
- Required information: 采访目标、采访对象、授权范围、转写片段、已核验引语、主题、可发布摘录、后续问题。
- Recommended components: `Quote`（保留关键原话）、`InsightCard`（分离解释与证据）、`ReferenceList`（回到原始素材）。
- Example: [采访记录](../template-examples/content-creation/interview-record.mdx)

## Family Quality Rules

- 事实、判断、未知项和下一步必须可区分。
- 只有真实存在的来源、负责人、日期和数字才能写成确定信息。
- Markdown 能表达清楚时不要强行使用组件。
