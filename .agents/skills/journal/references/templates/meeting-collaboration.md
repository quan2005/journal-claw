# Meeting Collaboration Templates

## Family Boundary

- Recognition signal: 多方发言、议题推进、分歧、决定或行动承诺。
- Expected output: 把会议素材压缩为可追踪的结论、未决问题和后续责任。
- Routing rule: 以材料要完成的工作为准，不按单个关键词分类；会议产出的独立规格文档只有在用户明确要求时才切换家族。

## Subtypes

### brainstorm

- Classification signal: 头脑风暴记录相关素材，且主要任务与标题一致。
- Expected output: 头脑风暴记录；把会议素材压缩为可追踪的结论、未决问题和后续责任。
- Required information: 问题边界、想法主题、筛选标准、入选方向、实验。
- Recommended components: `Cards`（按主题聚类想法）、`ComparisonMatrix`（用同一标准收敛）、`Steps`（安排最小实验）。
- Example: [头脑风暴记录](../template-examples/meeting-collaboration/brainstorm.mdx)

### customer-visit

- Classification signal: 客户拜访记录相关素材，且主要任务与标题一致。
- Expected output: 客户拜访记录；把会议素材压缩为可追踪的结论、未决问题和后续责任。
- Required information: 访谈目标、客户画像/当前流程、触发事件、任务/需求、现有替代方案、反对意见、购买/扩展信号、商务/产品跟进。
- Recommended components: `Quote`（保留关键原话）、`InsightCard`（分离解释与证据）、`ReferenceList`（回到原始素材）。
- Example: [客户拜访记录](../template-examples/meeting-collaboration/customer-visit.mdx)

### daily-standup

- Classification signal: 每日站会记录相关素材，且主要任务与标题一致。
- Expected output: 每日站会记录；把会议素材压缩为可追踪的结论、未决问题和后续责任。
- Required information: 迭代目标、成员、昨日承诺完成情况、今日最小推进、阻塞/决策请求、需要协助人、状态变化、升级项。
- Recommended components: `StatGroup`（提供紧凑状态快照）、`Table`（呈现阻塞与责任）、`Steps`（说明下一步顺序）。
- Example: [每日站会记录](../template-examples/meeting-collaboration/daily-standup.mdx)

## Family Quality Rules

- 事实、判断、未知项和下一步必须可区分。
- 只有真实存在的来源、负责人、日期和数字才能写成确定信息。
- Markdown 能表达清楚时不要强行使用组件。
