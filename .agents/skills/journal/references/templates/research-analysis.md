# Research Analysis Templates

## Family Boundary

- Recognition signal: 研究问题、样本、数据、证据、发现、限制或假设。
- Expected output: 把来源材料转化为有证据边界的判断和下一步验证。
- Routing rule: 以材料要完成的工作为准，不按单个关键词分类；会议产出的独立规格文档只有在用户明确要求时才切换家族。

## Subtypes

### business-analysis

- Classification signal: 商业分析相关素材，且主要任务与标题一致。
- Expected output: 商业分析；把来源材料转化为有证据边界的判断和下一步验证。
- Required information: 商业模式、客户/渠道、成本结构、收入结构、单位经济、战略影响、风险、建议/下一步验证。
- Recommended components: `Metrics`（说明数据或样本范围）、`BarChart`（比较核心量级）、`InsightCard`（分离结论与数据）。
- Example: [商业分析](../template-examples/research-analysis/business-analysis.mdx)

### competitor-analysis

- Classification signal: 竞品分析相关素材，且主要任务与标题一致。
- Expected output: 竞品分析；把来源材料转化为有证据边界的判断和下一步验证。
- Required information: 竞品集合、客户任务/购买标准、对比维度、对方优势证据、对方弱点证据、定位判断、可差异化机会、待验证盲区。
- Recommended components: `ComparisonMatrix`（统一比较维度）、`InsightCard`（提炼差异含义）、`Verdict`（给出有边界的结论）。
- Example: [竞品分析](../template-examples/research-analysis/competitor-analysis.mdx)

### data-analysis

- Classification signal: 数据分析相关素材，且主要任务与标题一致。
- Expected output: 数据分析；把来源材料转化为有证据边界的判断和下一步验证。
- Required information: 分析问题、数据范围/口径、基线/对照、指标变化、异常与排除、解释假设、建议、下一步验证。
- Recommended components: `Metrics`（说明数据或样本范围）、`BarChart`（比较核心量级）、`InsightCard`（分离结论与数据）。
- Example: [数据分析](../template-examples/research-analysis/data-analysis.mdx)

### experiment-report

- Classification signal: 实验报告相关素材，且主要任务与标题一致。
- Expected output: 实验报告；把来源材料转化为有证据边界的判断和下一步验证。
- Required information: 假设、实验设计、样本/分流、指标与成功标准、结果、异常/污染、决策、下一步验证。
- Recommended components: `Steps`（明确实验执行顺序）、`Metrics`（记录成功指标）、`DecisionRecord`（基于结果做决定）。
- Example: [实验报告](../template-examples/research-analysis/experiment-report.mdx)

### feasibility-analysis

- Classification signal: 可行性分析相关素材，且主要任务与标题一致。
- Expected output: 可行性分析；把来源材料转化为有证据边界的判断和下一步验证。
- Required information: 约束、价值假设、技术假设、商业/成本假设、可行性判断、所需验证、风险、决策。
- Recommended components: `Verdict`（先给评估结果）、`Table`（列出约束和验证）、`Steps`（安排降低不确定性的动作）。
- Example: [可行性分析](../template-examples/research-analysis/feasibility-analysis.mdx)

### feasibility

- Classification signal: 可行性分析相关素材，且主要任务与标题一致。
- Expected output: 可行性分析；把来源材料转化为有证据边界的判断和下一步验证。
- Required information: 约束、价值假设、技术假设、商业/成本假设、可行性判断、所需验证、风险、决策。
- Recommended components: `Callout`（声明硬约束和停止条件）、`Checklist`（快速检查最小前提）、`Verdict`（给出继续研究或停止的初筛结论）。
- Example: [可行性分析](../template-examples/research-analysis/feasibility.mdx)

### risk-assessment

- Classification signal: 风险评估相关素材，且主要任务与标题一致。
- Expected output: 风险评估；把来源材料转化为有证据边界的判断和下一步验证。

### user-research

- Classification signal: 用户研究相关素材，且主要任务与标题一致。
- Expected output: 用户研究；把来源材料转化为有证据边界的判断和下一步验证。
- Required information: 样本与招募条件、研究方法、行为/痛点证据、关键原话、洞察假设、机会点、样本限制、后续验证。
- Recommended components: `Quote`（保留关键原话）、`InsightCard`（分离解释与证据）、`ReferenceList`（回到原始素材）。
- Example: [用户研究](../template-examples/research-analysis/user-research.mdx)

## Family Quality Rules

- 事实、判断、未知项和下一步必须可区分。
- 只有真实存在的来源、负责人、日期和数字才能写成确定信息。
- Markdown 能表达清楚时不要强行使用组件。
