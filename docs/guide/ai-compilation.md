# AI 编译原理

谨迹的核心引擎是一个内置的 LLM 编译管线。理解它的工作原理，有助于你更好地使用谨迹。

## 编译管线

每次你提交一份新素材（文件、粘贴文本、文档），谨迹幕后执行：

```
素材接收
  → 预处理（文本提取 / 图片分析）
  → AI 上下文装配（相邻条目 + 相关画像 + 近期素材）
  → LLM 编译（Anthropic Messages API / 多厂商兼容）
  → 结构化输出（标题、标签、摘要、正文）
  → 写入 workspace/yyMM/DD-title.md
  → 发出 journal-updated 事件
  → 前端自动刷新
```

## 增量编译

谨迹不是每次都重新处理整个知识库，而是**增量编译**：

- 新素材只与近期条目（通常前 5-10 条）组合为上下文
- AI 检查新素材与旧条目的关联：是延续？补充？矛盾？
- 如果是延续（如同一会议的第二批会议纪要），AI 会更新相关条目而非创建冗余条目
- 如果是新主题，AI 创建独立的新条目

这样既保持了处理速度，又避免了条目碎片化。

## 结构化输出

AI 编译生成的每一条知识条目都包含 YAML frontmatter + Markdown 正文：

```markdown
---
title: "2025年度产品规划讨论"
tags: ["产品规划", "战略", "Q2"]
date: 2025-05-07
sources:
  - type: document
    path: raw/产品roadmap-v3.pdf
  - type: text
    path: raw/会议纪要-20250507.md
summary: "讨论了Q2产品方向，确定了三个优先级最高的功能..."
---

## 会议要点

1. Q2 确认优先开发 A/B/C 三个功能
2. 竞品分析显示 D 方向暂时搁置
...
```

### Frontmatter 字段

| 字段 | 说明 |
|---|---|
| `title` | AI 生成的描述性标题 |
| `tags` | 提取的关键词标签 |
| `date` | 素材提交日期 |
| `sources` | 对应的原始素材列表 |
| `summary` | 一段话摘要，适合快速浏览 |

## AI 提供商

谨迹通过统一的 Messages API 协议支持多厂商：

| 提供商 | 底层模型 | 说明 |
|---|---|---|
| Anthropic | Claude 系列 | 原生支持，推荐 |
| 火山方舟 | Doubao 系列 | 需配置 Endpoint ID |
| 智谱 AI | GLM 系列 | 国内优质模型 |
| 阿里云百炼 | Qwen 系列 | OpenAI 兼容接入 |

所有 API Key 安全存储在 macOS Keychain 中。

内置 LLM 引擎支持 **tool use（工具调用）** 循环——AI 可以主动调用文件读取、条目更新等工具来完成复杂编译任务。

## 处理队列

在设置面板中可以看到处理队列状态。素材按提交顺序排队：

- **排队中** — 等待 AI 处理
- **编译中** — AI 正在生成条目
- **已完成** — 条目已写入时间线
- **失败** — 可点击查看错误并重试
