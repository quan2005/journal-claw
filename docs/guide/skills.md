# 技能插件

技能（Skills）是谨迹的插件系统——通过 `SKILL.md` 文件定义自定义处理流程，扩展 AI 的能力。

## 什么是技能

技能是一个 Markdown 文件，使用 YAML frontmatter 定义元数据，正文包含给 AI 的指令。AI 不会把所有技能全文常驻放进系统提示词；系统只告诉 AI 有可用技能，并提供 `load_skill` 工具。需要某个技能时，AI 调用 `load_skill` 读取对应 `SKILL.md`。

```
技能 = 元数据（名称与描述） + 指令（如何处理） + 按需加载机制
```

## 技能文件结构

```markdown
---
name: meeting-minutes
description: 会议纪要整理技能
---

# 会议纪要整理

当素材包含会议内容时，请按以下格式整理：

1. 提取会议主题和时间
2. 列出参会人员
3. 按议题分组整理讨论要点
4. 提炼决策结论
5. 列出待办行动项
```

## 技能存放位置

技能文件可以放在两个位置：

| 位置                        | 作用范围   | 说明                         |
| --------------------------- | ---------- | ---------------------------- |
| `workspace/.agents/skills/` | 当前工作区 | 应用启动时会写入内置技能模板 |
| `~/.agent/skills/`          | 全局       | 开启全局技能后，对工作区生效 |

## 触发机制

当前实现是 **描述引导 + 显式加载**：

- 系统提示词只包含“有可用 Skills，需要时调用 `load_skill`”。
- `load_skill` 工具 schema 会列出可用技能名称和 description 摘要。
- 当用户输入 `/journal`、`/lint` 等技能名，或 AI 判断任务需要某个技能时，AI 调用 `load_skill` 加载完整规则。
- 多个技能可以在同一任务中按需先后加载，例如写日志时先加载 `/journal`，修改档案前再加载 `/identity-profiling`。

### 描述写法

`description` 是模型判断是否加载技能的主要线索，应写清楚：

- 什么时候使用这个技能
- 什么时候不要使用这个技能
- 这个技能读写哪些区域
- 是否依赖其他技能

## 自定义场景示例

### 日报整理技能

```yaml
description: '整理日报、周报和每日工作记录时使用。提取已完成事项、阻塞、明日计划和待办。不要用于会议纪要。'
```

指示 AI 按"做了什么 → 遇到什么问题 → 明日计划"三段整理。

### 代码审查技能

```yaml
description: '整理代码审查、PR 评审和技术反馈时使用。提取变更点、风险、决策和后续行动。'
```

指示 AI 提取代码变更点、潜在问题、优化建议。

### 客户沟通记录

```yaml
description: '整理客户沟通记录时使用。提取客户需求、承诺事项、决策、风险和下一步行动。'
```

指示 AI 提取客户需求、承诺事项、下一步行动。

## 管理与调试

- 在设置 → 技能中查看当前工作区和全局可用技能
- AI 处理失败时，可以查看日志中的 `load_skill: skill-name`，确认是否加载了预期技能
- 技能规则过大时，把细节拆到 `references/`，让 `SKILL.md` 只保留触发边界和读取顺序
