apps/web/src/runtime/srcdoc.ts — buildSrcdoc() 桥接注入管道
export function buildSrcdoc(html: string, options: SrcdocOptions = {}): string {
  // 1. Fragment → Full Doc（与 brainstorming visual companion 同模式）
  const wrapped = isFullDoc ? html : `<!doctype html><html>...<body>${html}</body></html>`;

  // 2. 桥接注入管道（顺序重要）
  const withOdIds     = annotateMissingOdIds(wrapped);          // 元素标记
  const withBase      = injectBaseHref(withOdIds, base);          // 相对路径
  const withShim      = injectSandboxShim(withBase);              // ★ 核心安全
  const withFocus     = injectPreviewFocusGuard(withShim);        // ★ 焦点防护
  const withDeck      = injectDeckBridge(withFocus);              // PPT 翻页
  const withSelection = injectSelectionBridge(withDeck);         // 元素选择
  const withPalette   = injectPaletteBridge(withSelection);       // 调色板
  const withEdit      = injectManualEditBridge(withPalette);      // 手动编辑
  const withTweaks    = injectTweaksBridge(withEdit);             // 面板切换
  const withSnapshot  = injectSnapshotBridge(withTweaks);        // 截图
  return injectSrcdocTransportActivationBridge(withSnapshot); // 延迟激活
}

Sandbox Shim（★ 谨迹最需要）

因为 sandbox="allow-scripts" 不含 allow-same-origin， localStorage/sessionStorage 会抛异常。 Shim 用内存 Map 模拟这两个 API，让依赖 Web Storage 的 artifact 正常运行。 同时拦截锚点链接和 target="_blank"。

Focus Guard（★ 谨迹需要）

重写 window.focus() 和 HTMLElement.prototype.focus()， 仅在用户交互 1 秒内才允许元素获得焦点。 防止嵌入内容劫持键盘焦点（意外触发快捷键等）。

3 差距项 & 整合策略

按"可直接复用 / 需改造 / 需新建"分类

复用
Streaming Artifact Parser（流式解析器）
Generator 模式的 XML 标签解析器几乎可以直接复制到谨迹的 conversation streaming 管道中。Open Design 的 parser.ts 只有 250 行，零依赖，纯逻辑。在谨迹的 useConversation.ts 中对 streaming text 块调用 feed()，yield 出 artifact:start/chunk/end 事件。
源：apps/web/src/artifacts/parser.ts
复用
Sandbox Shim（存储 polyfill）
injectSandboxShim() 的核心逻辑（in-memory storage + 锚点/外链拦截）完全通用，与业务无关。直接复制到谨迹的 HTML 预处理管道。
源：apps/web/src/runtime/srcdoc.ts:611-675
复用
Preview Focus Guard（焦点防护）
在谨迹中嵌入的 HTML 内容可能会调用 .focus() 劫持键盘。这个 40 行的脚本直接复制即可。
源：apps/web/src/runtime/srcdoc.ts:677-710
改造
Fragment → Full Doc 包裹
两种现有模式：brainstorming 的 frame-template.html 包裹（Apple 主题），Open Design 的 buildSrcdoc 最小外壳。谨迹需要自己的包裹器：注入谨迹主题 CSS 变量 + 琥珀金 accent + 系统字体。
参考：srcdoc.ts buildSrcdoc() + frame-template.html
改造
主题同步（Theme Bridge）
Open Design 的 palette bridge 是换色调色板。谨迹需要的是 dark/light 主题同步——通过 postMessage 告诉 iframe 当前主题，iframe 内监听并切换 CSS 类名。谨迹已有 MutationObserver 尝试，替换为 postMessage 桥接更可靠。
参考：injectPaletteBridge() 的 postMessage 模式
新建
Sandboxed HTML Preview 组件
新建一个 SandboxPreview 组件，替代 DetailView 中无 sandbox 的 iframe。核心：<iframe sandbox="allow-scripts" srcdoc={...} />，并将 sandbox shim + focus guard 注入 srcdoc。
新建：src/components/SandboxPreview.tsx
新建
Artifact 渲染器注册表
类似 Open Design 的 renderer-registry.ts。按 artifactType 分发渲染器：html → SandboxPreview，markdown → MarkdownRenderer，react-component → 错误/不支持。
新建：src/artifacts/renderer-registry.ts
新建
Conversation Streaming 管道扩展
在现有的 conversation-stream 事件处理中插入 ArtifactParser，将 artifact 事件独立发射（或合并到现有 stream 中）。需要新增 artifact:start/chunk/end 事件类型。
改动：src-tauri/src/conversation.rs + src/hooks/useConversation.ts

4 谨迹的桥接注入管道（设计草案）

比 Open Design 精简得多——只保留安全必需的桥接 + 主题同步

谨迹 SandboxPreview 的 buildSrcdoc() — 精简版管道
export function buildJournalSrcdoc(html: string, options: {
  baseHref?: string;      // 资源相对路径解析
  theme: 'light' | 'dark'; // 主题注入
}): string {

  // 1. Fragment → Full Doc（注入谨迹主题 CSS 变量）
  const wrapped = isFullDoc(html) ? html : wrapJournalShell(html, options.theme);

  // 2. 核心安全桥接（从 Open Design 直接复用）
  const withBase   = injectBaseHref(wrapped, options.baseHref);
  const withShim   = injectSandboxShim(withBase);     // ★ storage polyfill
  const withFocus  = injectPreviewFocusGuard(withShim); // ★ 焦点防护

  // 3. 谨迹专属桥接
  const withTheme  = injectThemeBridge(withFocus, options.theme); // 主题同步

  return withTheme;
}
wrapJournalShell()

包裹完整的 HTML 文档，head 中包含谨迹的 CSS 变量定义（--amber, --bg, --text 等），同步注入当前主题 class。

injectThemeBridge()

监听 message 的 od:theme 事件，切换 <html> 的 dark/light class。与谨迹的 useTheme hook 通过 postMessage 同步。

injectSandboxShim()

从 Open Design 直接复制。内存 Map 模拟 localStorage/sessionStorage，拦截锚点导航和 target="_blank"。

5 安全边界对比

Open Design — 沙盒预览安全模型

  • ✓ sandbox="allow-scripts" — 不含 allow-same-origin
  • ✓ Storage polyfill — localStorage/sessionStorage 不会崩溃
  • ✓ Focus guard — 不允许自动聚焦
  • ✓ CSP via sandbox — 禁止插件/表单提交/弹窗等
  • ✓ postMessage 隔离 — 仅有明确允许的消息类型
  • ✓ 模板安全验证 — 拦截 script/iframe/事件处理器
  • △ allow-scripts 允许执行 — 这是功能需求，非漏洞

谨迹 — 当前 HTML 预览安全模型

  • ✗ 无 sandbox 属性 — iframe 拥有完整权限
  • ✗ 无 storage shim — 不存在（因为没 sandbox 不需要）
  • ✗ 无 focus guard — HTML 可劫持键盘焦点
  • ✗ 无 CSP — index.html 无任何 CSP meta 标签
  • △ DOMPurify for markdown — 仅覆盖 marked 输出路径
  • △ Tauri 环境 — 非浏览器扩展，但仍有风险
  • ✗ Blob URL iframe src — 绕过了浏览器同源保护

7 重要发现：两个项目的 Fragment 包裹模式完全一致

Brainstorming Visual Companion
server.cjs:isFullDocument()
→ startsWith('<!doctype') or startsWith('<html')
→ Fragment → wrapInFrame(frame-template.html)
Open Design srcDoc Builder
srcdoc.ts:buildSrcdoc()
→ head.startsWith('<!doctype') or head.startsWith('<html')
→ Fragment → wrap minimal doctype shell

两者都采用了相同的设计决策：AI 只需写 HTML 片段，无需 <html> / <head> / <style> 样板代码。 系统自动检测并包裹完整文档外壳。区别在于包裹的内容——brainstorming 注入 Apple 风格的 frame UI（header/indicator bar）， Open Design 注入最小外壳 + 安全桥接。谨迹需要的是后者的安全模型 + 谨迹自身的设计主题。
