# Feature Specification: 首次启动引导体验

**Feature Branch**: `001-onboarding-experience`

**Created**: 2026-05-25

**Status**: Draft

**Input**: User description: "深入参考 open-design 项目的启动引导用户体验，为 JournalClaw 打造出色的首次使用引导流程。引导除了配置路径外，最重要的是配置大模型的 key。产品定位为纯粹笔记软件，语音转写和录音能力不纳入核心功能。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 首次启动的核心决策：工作区路径确认 (Priority: P1)

用户首次打开 JournalClaw 时，看到一个沉静、专业的欢迎界面，展示品牌标识和一句话定位。界面引导用户确认或自定义工作区路径（日志存储位置），这是使用应用的前提条件。用户看到默认路径（`~/Documents/journal/`），可以直接确认继续，也可以自定义路径。确认后进入下一步。

**Why this priority**: 工作区路径是 JournalClaw 运行的必要前提。没有工作区，日志无处存储，所有后续功能无法使用。这是第一个硬性决策点。

**Independent Test**: 清除应用状态后首次启动，验证欢迎界面出现、默认路径展示、确认/自定义路径均可正常进入下一步。

**Acceptance Scenarios**:

1. **Given** 用户首次启动 JournalClaw（无任何历史配置），**When** 应用加载完成，**Then** 显示欢迎界面，包含应用名称、品牌标识、一句话定位描述，以及默认工作区路径 `~/Documents/journal/` 和"确认并继续"按钮
2. **Given** 用户在欢迎界面看到默认工作区路径，**When** 用户点击"确认并继续"，**Then** 工作区在默认路径初始化，进入 AI 引擎配置步骤
3. **Given** 用户在欢迎界面，**When** 用户点击"自定义路径"选择其他目录，**Then** 系统使用所选目录创建工作区，进入 AI 引擎配置步骤
4. **Given** 用户选择了已存在日志内容的工作区路径，**When** 确认路径，**Then** 系统识别已有内容并正常加载（不覆盖、不报错）
5. **Given** 用户选择了无写入权限的路径，**When** 确认路径，**Then** 显示友好的错误提示，引导用户选择其他路径

---

### User Story 2 - 激活核心能力：AI 引擎配置 (Priority: P1)

工作区确认后，用户进入 AI 引擎配置步骤。这是引导中最重要的环节——没有大模型 API Key，JournalClaw 无法将导入的文件和文本处理为结构化日志。界面展示提供商选择（如 Anthropic、DeepSeek、豆包、Ollama 等），用户选择提供商并填入 API Key。提供"连接测试"按钮，让用户在继续前验证凭据可用。用户也可以跳过此步骤，在主界面的设置中稍后配置。

**Why this priority**: AI 引擎是 JournalClaw 核心价值的前提。参考 open-design 的 Runtime 选择步骤——他们把最关键的技术决策（本地 CLI vs BYOK）放在引导第一步。对 JournalClaw 而言，API Key 配置就是"关键决策点"。提供连接测试让用户立即获得"配置成功"的正向反馈，降低放弃率。

**Independent Test**: 在工作区确认后，验证 AI 引擎配置步骤出现，提供商选择、API Key 输入、连接测试按钮均可用，Skip 按钮可用。

**Acceptance Scenarios**:

1. **Given** 用户刚确认工作区路径，**When** 进入 AI 引擎配置步骤，**Then** 展示提供商选择器（含 Anthropic、DeepSeek 等至少 4 个选项）、API Key 输入框（含显示/隐藏切换）、"测试连接"按钮和"跳过"入口
2. **Given** 用户选择了提供商并填入 API Key，**When** 点击"测试连接"，**Then** 系统发起轻量测试请求，显示测试结果（成功/失败 + 具体信息，如延迟毫秒数或错误原因）
3. **Given** 用户连接测试成功，**When** 点击"继续"，**Then** 保存 AI 引擎配置，进入可选的能力展示步骤
4. **Given** 用户连接测试失败，**When** 查看错误信息，**Then** 显示明确的错误描述（如"API Key 无效"、"网络无法连接"、"账户余额不足"），引导用户修正
5. **Given** 用户不想在引导中配置 AI 引擎，**When** 点击"跳过"，**Then** 进入可选的能力展示步骤（或直接进入主界面），后续可在设置中配置
6. **Given** 用户选择了本地可用的提供商（如 Ollama），**When** 配置本地端点地址，**Then** 连接测试验证本地服务可用性

### User Story 3 - 选择性体验：了解两种输入方式 (Priority: P2)

AI 引擎配置完成后，用户进入一个可选的能力展示步骤。JournalClaw 定位为纯粹笔记软件，核心输入方式为两种：拖入文件自动分析和粘贴文本整理。界面以极度克制的视觉呈现这两种方式，每种配有一行简洁描述和一个可直接尝试的入口。用户可以直接尝试（此时 AI 引擎已配置好，尝试操作能走通完整流程），也可以跳过直接进入主界面。

**Why this priority**: 用户已经完成了两个关键配置，可以开始使用应用了。能力展示提供温和的引导，让用户了解"我能做什么"，并验证端到端流程可用（输入 → AI 处理 → 生成日志）。参考 open-design 的 About You 步骤的设计理念：完全可选，跳过即进入主界面。

**Independent Test**: AI 引擎配置后，验证可选的能力展示步骤出现，两种输入方式均展示，每个可独立尝试，Skip 按钮可用。

**Acceptance Scenarios**:

1. **Given** 用户刚完成 AI 引擎配置（或跳过），**When** 进入能力展示步骤，**Then** 展示两种输入方式（拖入文件、粘贴文本），每种配有图标、标题、一行描述
2. **Given** 用户在能力展示步骤，**When** 用户拖入一个文件到拖放区域，**Then** 文件被导入并开始 AI 处理，同时进入主界面
3. **Given** 用户在能力展示步骤，**When** 用户在粘贴区域粘贴文本，**Then** 文本被导入并开始 AI 处理，同时进入主界面
4. **Given** 用户在能力展示步骤，**When** 用户点击"跳过"或"进入应用"，**Then** 直接进入主界面，不显示任何引导内容
5. **Given** 用户通过能力展示步骤的某个输入方式触发了操作，**When** 操作启动，**Then** 平滑过渡到主界面，操作继续进行不中断

### User Story 4 - 引导完成后的空白页体验 (Priority: P3)

用户完成引导进入主界面后，面对的是尚未产生任何日志的空工作区。主界面不应展示"暂无日志"这类空状态提示文字，而是保持清净的空白列表区域，让用户的注意力自然聚焦到唯一的行动点——底部输入区域（拖放、粘贴、斜杠命令）。在详情面板区域展示一句温和的引导语（如"拖入一个文件或粘贴一段文字开始"），在用户产生第一条日志后自动消失。

**Why this priority**: 这是引导完成后的延续体验。空状态的设计决定了用户的第一印象是否清净、专业。参考 open-design 的 Recent Projects 条带在空态时完全不渲染的做法，避免视觉噪音。

**Independent Test**: 新工作区进入主界面，验证无"暂无日志"空状态文字，底部输入区域正常显示可用。

**Acceptance Scenarios**:

1. **Given** 用户首次进入空工作区的主界面，**When** 查看日志列表区域，**Then** 列表区域空白但不显示任何空状态提示文字或图标
2. **Given** 用户首次进入空工作区的主界面，**When** 查看底部，**Then** 输入区域完整展示，所有输入方式（拖放区域、斜杠命令、粘贴入口）均可正常使用
3. **Given** 用户在空工作区产生了第一条日志，**When** 第一条日志出现在列表中，**Then** 详情面板中的引导语自动消失，展示该日志内容

---

### Edge Cases

- 用户关闭欢迎界面（Cmd+W 或关闭窗口）后重新打开应用：应恢复到上次未完成的引导步骤，而非重新开始
- 用户在引导过程中系统休眠/崩溃后重启应用：引导状态应持久化，恢复到中断的步骤
- 用户通过命令行或外部方式修改了工作区路径后启动：检测到路径不存在或权限不足时的降级处理
- 用户在设置面板中切换工作区路径后：不应重新触发引导（引导仅限首次启动）
- 用户在多显示器环境下首次启动：引导窗口应出现在主显示器中央
- 用户系统级减少动效偏好开启时：所有引导步骤切换动画应降级为即时切换
- 深色/浅色主题：引导界面应正确响应主题设置，在引导流程中主题切换按钮可用
- 用户在引导中配置了 API Key 但后来在设置中删除：引导不重现，AI 功能在调用时正常报错提示
- 用户已有 config.json（如从旧版本升级）但 `onboarding_completed` 不存在：视为未完成引导，触发引导流程

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在首次启动且无历史配置时自动展示引导流程
- **FR-002**: 引导流程 MUST 包含三个步骤：工作区路径确认（步骤 0）、AI 引擎配置（步骤 1）、可选的能力展示（步骤 2）
- **FR-003**: 步骤 0 MUST 展示默认工作区路径 `~/Documents/journal/`，并提供"确认并继续"按钮和"自定义路径"入口
- **FR-004**: 系统 MUST 在确认工作区路径后自动初始化工作区目录结构（若不存在）
- **FR-005**: 每个引导步骤 MUST 提供显式的"跳过"入口，允许用户在任何步骤退出引导直接进入主界面
- **FR-006**: 步骤 1 MUST 展示提供商选择器（至少包含 Anthropic、DeepSeek、Ollama 等常用选项）、API Key 输入框（含显示/隐藏切换）、"测试连接"按钮
- **FR-007**: 步骤 1 MUST 在用户点击"测试连接"后发起轻量验证请求，展示明确的成功/失败结果（含具体错误原因）
- **FR-008**: 步骤 1 MUST 在连接测试成功后保存 AI 引擎配置，并在"继续"按钮上反映已配置状态
- **FR-009**: 步骤 2 MUST 展示两种核心输入方式（拖入文件、粘贴文本），每种均可直接触发对应操作
- **FR-010**: 引导完成状态 MUST 持久化为布尔值（`onboardingCompleted`），完成后再也不会重新触发
- **FR-011**: 引导过程中的步骤间切换 MUST 平滑过渡，动画时长不超过 300ms，不得使用弹跳或弹性缓动效果
- **FR-012**: 系统 MUST 尊重用户的减少动效系统偏好，当用户的系统级动效偏好为"减少动效"时，引导步骤切换应无动画、即时切换
- **FR-013**: 空工作区主界面 MUST NOT 显示空状态提示文字（如"暂无日志"），日志列表区域保持空白清净
- **FR-014**: 引导流程 MUST 展示步骤指示器（编号圆点 + 标签），允许用户点击已完成的步骤回退
- **FR-015**: 引导界面 MUST 正确响应深色/浅色主题，主题切换按钮在引导过程中保持可用
- **FR-016**: 工作区路径校验失败时 MUST 显示明确的中文错误提示，引导用户修正

### Key Entities

- **OnboardingState**: 引导进度的持久化状态，包含 `onboardingCompleted`（是否已完成引导）布尔值。区别于应用配置中的其他偏好设置，该状态一旦设为 `true` 则永不复用。
- **WorkspacePath**: 用户选择的工作区根路径，是应用运行的必要配置。引导完成后写入 workspace 配置，后续可通过设置面板修改。
- **AIEngineConfig**: 复用现有的 AI 引擎配置实体（`ProviderEntry`：provider ID、API Key、base URL、model），引导步骤 1 通过现有 `set_engine_config` 命令写入。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从首次启动到进入主界面的时间不超过 30 秒（使用默认路径 + 配置 API Key + 跳过能力展示）
- **SC-002**: 用户从首次启动到完成第一条日志输入（拖入文件/粘贴文本）的时间不超过 120 秒
- **SC-003**: 引导完成率达 85% 以上（即用户不会因引导流程而放弃使用应用）
- **SC-004**: AI 引擎连接测试成功率达 90% 以上（对于填入有效凭据的用户）
- **SC-005**: 引导步骤间的切换动画在任意设备上均保持 60fps
- **SC-006**: 引导完成后，用户不会在后续任何一次启动中再次看到引导界面（100% 确定）
- **SC-007**: 引导过程中触发的任何操作（文件导入、粘贴文本）在过渡到主界面后不中断、不丢失数据

## Assumptions

- 用户使用的 macOS 版本支持应用正常运行（macOS 14+）
- 默认工作区路径 `~/Documents/journal/` 在绝大多数用户的文件系统中是可写的
- JournalClaw 定位为纯粹笔记软件，语音转写和录音不作为核心功能
- 引导流程不需要网络连接（工作区初始化为纯本地操作），但 AI 引擎配置步骤需要网络连接进行连接测试
- 引导界面使用与应用主体相同的设计语言和组件体系（不引入新的设计范式）
- 隐私相关披露（如数据收集说明）遵循 open-design 的做法：引导完成后通过设置面板或独立提示处理，不混入引导流程
- AI 引擎配置步骤复用现有的提供商配置系统（`set_engine_config` 命令和 `SectionAiEngine` 中的提供商选择逻辑）
- 对于从旧版本升级且已有 `config.json` 的用户，如果 `onboarding_completed` 字段不存在（缺少该 key），应触发引导流程
