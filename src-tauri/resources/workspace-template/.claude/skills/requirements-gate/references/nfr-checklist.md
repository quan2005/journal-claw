# 非功能需求缺口扫描 NFR Gap Scanner

功能需求漏了，开发时会被发现；非功能需求漏了，上线后才会被发现——而且通常以事故的形式。逐项过一遍，**不适用的写 "N/A + 原因"**，强迫自己证明"确实不适用"而不是"没想到"。

| 维度 | 触发问题 | 典型遗漏后果 |
|---|---|---|
| 性能 | 预期数据量/并发量？最慢可接受多少？ | 演示流畅，真实数据卡死 |
| 安全 / 权限 | 谁能用这功能？越权访问路径堵住了吗？ | 普通用户看到管理数据 |
| 数据 / 隐私 | 涉及个人信息/敏感数据吗？留存与脱敏策略？ | 合规风险，日志泄露 PII |
| 可靠性 / 降级 | 依赖方挂了怎么办？有兜底吗？ | 第三方故障导致整功能不可用 |
| 可观测性 | 出问题时靠什么定位？埋点/日志/指标够吗？ | 线上故障只能靠用户截图排查 |
| 回滚策略 | 上线出问题能一键回退吗？数据变更可逆吗？ | 带数据迁移的功能无法回滚 |
| 兼容性 | 旧版本客户端/已有数据/现有 API 调用方受影响吗？ | 升级后老用户数据打不开 |
| 多语言 / 多地区 | 文案、时区、货币、法规差异？ | 海外用户时间显示错误 |
| 运营 / 客服 | 增加人工处理负担吗？需要 SOP 吗？ | 客服不知道新功能怎么答 |
| 风控 / 滥用 | 会被刷吗？批量/自动化滥用的代价？ | 导出接口被爬虫薅崩 |
| 成本 | 算力/存储/第三方 API 调用费随量增长吗？ | 量上来后账单失控 |

## L3 深度评审的强制项

需求触碰以下任一项时（即 L3 判定条件），对应维度**不允许 N/A**：

- 数据契约变更 → 兼容性、回滚策略
- 权限模型变更 → 安全/权限、可观测性
- 计费/定价 → 成本、风控/滥用、数据/隐私
- 对外 API → 兼容性、性能、安全/权限
- 不可逆迁移 → 回滚策略（必须给出迁移失败的处置预案）
