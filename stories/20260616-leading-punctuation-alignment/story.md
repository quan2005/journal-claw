# MDX 预览行首符号左对齐修复

> 一句话概括：**为阅读 MDX 日志的知识工作者解决行首符号突出阅读栏的问题**

## 用户故事（Connextra）

作为 **正在预览长篇 MDX 日志的知识工作者**，
当我 **阅读以 `【`、`[`、引号、括号等符号开头的正文行**，
我希望 **这些行和普通段落共享同一条左边缘**，
以便 **扫读时不会被符号开头的行打断阅读节奏**。

## 真实用户问题（背景，讲故事）

用户在截图中指出“只要有符号，就没对齐”。这说明上一轮阅读栏宽度和普通正文左对齐已经不足以覆盖行首符号场景：符号开头的正文会向阅读栏外侧突出，形成肉眼可见的左移。[证据：用户 2026-06-16 截图与反馈]

### 现状失败模式

- 用户现在只能靠视觉忍受或手动改内容，避免行首符号。
- 失败原因是符号开头的行与普通文字行不共享同一视觉左边界。
- 支撑证据：用户截图中 `【幻灯片...】`、`【停顿】` 相比普通段落向左突出。

## 成功标准（脊柱 Q4）

### 用户行为变化

做完后，阅读 MDX 日志的用户会：
- 看到符号开头的正文行与普通段落左边缘一致：有偏移 → 无肉眼可见偏移
- 不再需要改写内容来规避行首符号：需要规避 → 不需要规避

假设依据：以上基于用户截图反馈。验证方式为真实 CSS cascade 下的 computed style 与局部截图/视觉检查。

## 验收标准（Given-When-Then）

### AC-1 — 行首符号不突出阅读栏
- **Given** 用户打开包含普通段落和 `【...】` 这类符号开头行的 MDX 预览
- **When** 用户扫读正文
- **Then** 符号开头行应与普通段落从同一阅读栏左边缘开始
- **And** 不应出现符号向左悬挂到阅读栏外的效果

### AC-2 — 既有阅读栏分层保持不变
- **Given** 用户查看包含普通正文、代码块、表格或复杂 MDX 组件的预览
- **When** 用户滚动阅读
- **Then** 普通正文仍保持稳定阅读栏
- **And** 代码块、表格或复杂 MDX 组件仍可使用可用宽度

## 三类边界（脊柱 Q5 · Won't · 输出闸必填）

- **不为哪些用户做**：不为需要传统出版排版悬挂标点的用户做；日志预览优先对齐和扫读。
- **不在哪些场景出现**：不调整编辑器输入行为、源码模式或日志内容本身。
- **不解决哪些相关但不同的问题**：不重新设计列表缩进、引用块视觉风格、全应用字体体系或 MDX 渲染架构。
