# MDX 全屏预览正文宽度跟随窗口

> 一句话概括：**为全屏预览 MDX 日志的知识工作者解决正文没有吃满可用宽度、提前换行的问题**

## 用户故事（Connextra）

作为 **正在全屏预览长篇 MDX 日志的知识工作者**，
当我 **打开全屏或超宽窗口阅读正文段落**，
我希望 **普通正文、标题和引用块跟随内容区宽度展开**，
以便 **减少不必要换行，真正利用全屏阅读空间**。

## 真实用户问题（背景，讲故事）

用户在截图中标注“没有全屏”和“文字没有自适应全屏，就换行了”。这说明上一轮 `clamp(...)` 式自适应仍保留了最大正文宽度，上限在全屏场景下太早触发，导致正文没有使用右侧可用空间。[证据：用户 2026-06-16 截图与反馈]

### 现状失败模式

- 用户现在看到正文在全屏窗口中仍提前换行，右侧留出可继续使用的空间。
- 失败原因是正文宽度仍有 `--journal-prose-max` 上限，而不是跟随全屏内容区。
- 支撑证据：截图中正文行在可用内容区未结束前换行，用户明确指出“文字没有自适应全屏”。

## 成功标准（脊柱 Q4）

### 用户行为变化

做完后，全屏预览 MDX 日志的用户会：
- 看到普通正文跟随内容区展开：最大宽度截断 → 使用可用内容宽度
- 看到提前换行减少：全屏仍窄栏换行 → 全屏按内容区换行
- 仍保持左对齐和符号对齐：不偏移 → 同一左边缘

假设依据：以上基于用户截图反馈。验证方式为真实 CSS cascade 下的宽屏几何检查与目标样式测试。

## 验收标准（Given-When-Then）

### AC-1 — 全屏正文使用内容区宽度
- **Given** 用户在全屏或超宽窗口打开 MDX 预览
- **When** 正文包含普通段落、标题和引用块
- **Then** 这些正文块应使用可用内容区宽度
- **And** 不应再被固定最大阅读宽度提前截断换行

### AC-2 — 左对齐与行首符号不回退
- **Given** 用户阅读包含 `【...】`、普通段落、标题和引用块的 MDX 预览
- **When** 窗口宽度变化
- **Then** 这些正文块仍从同一左边缘开始
- **And** 行首符号不应向阅读栏外突出

### AC-3 — 复杂块宽度分层保持可用
- **Given** 用户查看包含代码块、表格、图片或复杂 MDX 组件的预览
- **When** 全屏阅读
- **Then** 复杂块仍可使用可用宽度
- **And** 不应因为正文全宽而出现额外缩窄或溢出

## 三类边界（脊柱 Q5 · Won't · 输出闸必填）

- **不为哪些用户做**：不为偏好固定出版式长文行宽的用户做；本场景以用户指出的全屏空间利用为优先。
- **不在哪些场景出现**：不调整源码模式、聊天面板、列表页卡片或 Ideas 工作台布局。
- **不解决哪些相关但不同的问题**：不新增阅读宽度设置，不重做详情页信息架构，不改变 MDX 组件语义。
