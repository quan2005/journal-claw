# MDX 预览宽屏阅读栏自适应

> 一句话概括：**为宽屏预览长篇 MDX 日志的知识工作者解决正文栏过窄、右侧大面积空白的问题**

## 用户故事（Connextra）

作为 **正在宽屏预览长篇 MDX 日志的知识工作者**，
当我 **打开正文内容较长、窗口宽度明显大于正文栏的日志预览**，
我希望 **正文阅读栏能随可用空间合理展开**，
以便 **减少右侧空白，扫读时不用忍受内容被挤在左侧小栏里**。

## 真实用户问题（背景，讲故事）

用户在截图中用红框标出正文右侧的大面积空白，并标注“空白，没有自适应”。这说明上一轮为了稳定左对齐把正文阅读栏固定在较窄宽度后，在宽屏预览场景产生了新的失败模式：内容没有使用足够的横向空间，视觉重心偏左。[证据：用户 2026-06-16 截图与反馈]

仓库真实渲染链路中，MDX 预览由 `MdxRenderer` 输出 `.md-content.mdx-content`，再叠加 `markdown.css`、`mdx.css` 和 `journal-blocks.css` 的宽度规则。[证据：AGENTS.md；src/components/MdxRenderer.tsx；src/styles/markdown.css；src/styles/mdx.css]

### 现状失败模式

- 用户现在只能接受右侧空白，或手动调整窗口/内容来规避。
- 失败原因是普通正文块共享固定 `--journal-prose-max`，宽屏下没有随容器增长。
- 支撑证据：截图中正文在左侧形成窄栏，右侧留出明显未使用区域。

## 成功标准（脊柱 Q4）

### 用户行为变化

做完后，宽屏预览 MDX 日志的用户会：
- 看到正文栏随宽屏合理变宽：固定窄栏 → 自适应展开
- 看到右侧无意义空白明显减少：大块空白 → 只保留必要留白
- 仍能保持长文扫读稳定：失控横向拉伸 → 有最大可读宽度

假设依据：以上基于用户截图反馈。验证方式为真实 CSS cascade 下的 computed style 与目标样式测试。

## 验收标准（Given-When-Then）

### AC-1 — 宽屏正文栏自适应展开
- **Given** 用户在宽屏窗口中打开 MDX 预览
- **When** 正文内容包含普通段落、标题和引用块
- **Then** 这些正文块应随可用宽度合理变宽
- **And** 不应被固定在导致右侧大面积空白的窄栏宽度

### AC-2 — 窄屏与左对齐不回退
- **Given** 用户在较窄窗口或普通窗口中打开同一 MDX 预览
- **When** 用户扫读标题、段落、引用块和符号开头行
- **Then** 正文块仍从同一左边缘开始
- **And** 行首符号不应向阅读栏外突出

### AC-3 — 复杂块仍使用可用宽度
- **Given** 用户查看包含代码块、表格、图片或复杂 MDX 组件的预览
- **When** 用户滚动阅读
- **Then** 这些复杂块仍可使用可用宽度
- **And** 不应被新的正文宽度上限压窄

## 三类边界（脊柱 Q5 · Won't · 输出闸必填）

- **不为哪些用户做**：不为需要严格出版排版固定行长的用户做；日志预览优先空间利用和扫读舒适。
- **不在哪些场景出现**：不调整源码编辑模式、列表页卡片、聊天面板或非日志详情的布局。
- **不解决哪些相关但不同的问题**：不重做详情页整体信息架构，不新增用户可配置阅读宽度，不改变 MDX 组件语义。
