# Browse 页眉 + 想法去冗余 + 技能空态（codex 批次 2）

## 用户故事

作为一名在谨迹各页之间切换浏览的知识工作者，
我希望每页都有一致的身份感、信息不重复说两遍、空状态也有内容可用，
以便我在 Hub 页与 Browse 页之间切换时认知连贯，不浪费屏幕，不被冗余数字干扰。

## 背景与失败模式

[证据 G3] 技能/想法/自动化有 eyebrow + Playfair 巨标题；专题/核心画像/Timeline 直接裸列表侧栏，无任何标题锚点，像两套设计。用户已选「给 Browse 页加轻量页眉」。
[证据 G4] 想法页顶部三张统计卡（12 未完成 / 10 待探讨 / 3 有截止）与下方筛选 Tab 计数几乎完全重复。用户已选「删卡片，留筛选 Tab」。
[证据 G8] 技能页收藏=0 时整个中央画布只有一行「暂无收藏」，约 70% 空间浪费。用户倾向收藏为空时默认渲染技能列表。

## 成功标准（GWT 验收）

- **AC-1**（Browse 页眉 · 方案 A 单行标签，2026-06-28 用户看渲染后修订）Given 用户进入「专题」/「核心画像」/「Timeline」任一 Browse 页，When 渲染，Then 顶部是单行紧凑页眉：一个橙色（--record-btn）小图标 + 该页名称标签（--font-body ~12px/600），整体高度约 28–32px，无大号 Playfair 标题、无独占行副标题；三页共用同一 `BrowsePaneHeader` 组件，仅图标/标签不同。
  - 背景：初版按 Hub 同款（Playfair --text-xl + 副标题，~130px）实现，用户反馈在以扫读为主的 Browse 页上太占空间、信息价值低，改为方案 A。
- **AC-2**（想法去冗余）Given 用户进入想法页，When 渲染，Then 顶部三张统计卡被移除，可点击的筛选 Tab（含计数）保留为唯一的状态总览/筛选入口；页面不再两处显示同一组数字；「新建想法」按钮位置不再浮空错位、与筛选区对齐。
- **AC-3**（技能空收藏态）Given 用户在技能页且收藏=0，When 渲染中央画布，Then 默认展示技能列表（如「全局/内置」分组，本就有数据），而非整屏空提示；仍保留引导用户收藏的轻量提示（如卡片上的 ☆ 入口）。
- **AC-4**（不回退）Given 上述改动，When 运行 `npm run build` 与 `npm test`，Then 全部通过；改动复用结构化 token（圆角/阴影/边框/字体三栈），无新增硬编码数值。

## 边界（Won't）

- 不改 Browse 页的列表内容、排序、点击行为（仅加页眉）。
- 不改想法的筛选逻辑与计数口径（仅删统计卡这一展示层）。
- 不改技能的收藏机制本身（仅改空收藏时画布默认渲染什么）。
- 不做 G9（卡片/行基元统一）——那是后续独立重构。

## 交棒 design（实现层）

- Browse 页眉应抽为可复用组件（eyebrow + 标题 + 副标题），三页共用，勿各写一份。
- 想法删卡后顶部留白与按钮对齐，按 8pt 网格与现有 Hub 页眉间距对齐。
- 技能空态默认列表：复用现有技能列表渲染，不新造列表组件（CLAUDE.md Rule1）。
- 所有视觉改动以 computed style 真实渲染链为准（CLAUDE.md 约束7）。
