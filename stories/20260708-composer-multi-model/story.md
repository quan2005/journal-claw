# Agent 输入框重设计 + 多厂商多模型按需切换

> 一句话概括：**为用内置引擎工作的知识工作者，提供在发消息前随手切换不同厂商模型的能力，并把输入框重设计为承载该能力的形态**

依赖：`STORY-20260708-remove-cli-engines` 完成后实施（引擎唯一化后，"选模型"取代"选引擎"成为唯一选择维度）。

## 用户故事（Connextra）

作为 **在谨迹右侧 Agent 栏与内置引擎对话的知识工作者**，
当我 **不同任务想用不同厂商的不同模型（如快问题用便宜快模型、难问题用强模型）**，
我希望 **在设置中配好多个厂商的多个模型后，发送任何一条消息前都能在输入框上随手切换**，
以便 **按任务性质选模型，不用改配置或重开会话**。

## 真实用户问题（背景，讲故事）

引擎收敛为内置 pi 引擎后，模型成为唯一需要选择的维度。当前设置中已有模型配置能力（单一配置），但：一是后台只支持一套配置，无法同时配好多个厂商的多个模型备用；二是前台输入框没有模型选择入口，切换模型必须去设置里改，打断对话流。同时输入框本身需要整体重新设计，视觉参考稿（见本目录 mockup / 用户提供截图）：多行输入区 + 底部操作行 + 左下角模型选择 pill「● 内置 · 内置 pi 引擎 · deepseek-chat ▾」。

[证据] 用户提供的设计截图（输入框含 placeholder "Ask me anything"、📎、🎤、发送键、模型 pill）。
[证据] 用户确认：设置中模型配置"本来就有，只是做微小升级"。

### 现状失败模式

- 现在怎么解决：全程用一个固定模型；要换就去设置里改全局配置。
- 为什么不够好：任务粒度的模型切换要走"离开对话 → 设置 → 改配置 → 回来"，代价高到用户干脆不换，所有任务凑合用同一个模型。
- 基线：切一次模型 ≥4 步跨界面操作 → 目标 2 步以内、不离开输入框。

## 成功标准（脊柱 Q4）

### 用户行为变化

- 换模型的操作路径：跨界面 ≥4 步 → 输入框内 2 步（点 pill → 选模型）。
- 可备用的模型数量：1 个 → 用户配置的任意多个（跨厂商）。
- 切换生效延迟：需重开会话/改设置 → 下一条消息立即生效。

⚠️ 假设依据：直觉 + 业界惯例（主流 AI chat 产品均在输入框提供模型切换）。用户即本人，日常使用中验证。

## 验收标准（Given-When-Then）

### AC-1 — 设置中配置多厂商多模型

- **Given** 用户打开设置中的模型配置区
- **When** 为多个厂商（如 deepseek、anthropic、openai）分别填入凭证并各添加多个模型
- **Then** 所有配置成功保存，重启应用后仍在
- **And** 每个厂商可配多个模型，多个厂商可同时存在

### AC-2 — 输入框内切换模型

- **Given** 用户已配置 ≥2 个模型，正在 Agent 栏对话
- **When** 点击输入框上的模型 pill 并从列表中选择另一个模型
- **Then** pill 立即显示新选中的模型
- **And** 列表按厂商分组展示所有已配置模型

### AC-3 — 切换后下一条消息立即生效

- **Given** 用户在会话中途从模型 A 切到模型 B
- **When** 发送下一条消息
- **Then** 该消息由模型 B 处理（会话中可观察到模型标识变化），无需重开会话

### AC-4 — 默认模型 = 上次选择

- **Given** 用户上次会话最后选用了模型 B
- **When** 关闭并重新打开应用、开始新会话
- **Then** 输入框 pill 默认显示模型 B

### AC-5 — 输入框整体重设计落地

- **Given** 用户查看右侧 Agent 栏输入框
- **When** 对照确认后的视觉稿
- **Then** 布局与 `mockup.html`（已确认版）一致：多行输入区 + 单行紧凑操作行（附件、模型 pill、思考等级 pill、发送键同行），无内外双边框
- **And** 遵循 docs/DESIGN.md 结构化 token 与单一信号橙规范

### AC-6 — 思考等级切换

- **Given** 用户正在 Agent 栏对话
- **When** 点击输入框上的思考等级 pill 并在 低 / 中 / 高 三档中选择
- **Then** pill 立即显示新档位，下一条消息按该档位处理
- **And** 与模型选择一样记住上次选择，重启后保持

## 三类边界（Won't）

- **不为哪些用户做**：不考虑未配置任何模型的空状态之外的引导教育（唯一用户即维护者，自己会配）。
- **不在哪些场景出现**：不做麦克风/语音输入功能（音频能力已于 M8-b 下线，视觉稿中的 🎤 仅为参考稿元素，见待确认 Q1）；不做发送中途换模型（仅影响下一条消息）。
- **不解决哪些相关但不同的问题**：不做模型自动路由/智能选择（永远手动选）；不做按模型计费统计；不做模型能力对比展示；不改 Agent 栏输入框以外的对话区域设计。
