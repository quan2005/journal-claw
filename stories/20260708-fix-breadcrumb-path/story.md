# 修复：面包屑按真实路径显示

> 一句话概括：**为浏览文件的用户修复顶部面包屑凭空多出「专题」前缀的问题，面包屑严格对应文件的真实路径**

## 用户故事（Connextra）

作为 **在谨迹中打开文件的用户**，
当我 **查看顶部面包屑确认当前文件的位置**，
我希望 **面包屑逐段对应文件的真实目录路径**，
以便 **准确知道文件在哪，并信任面包屑做定位**。

## 真实用户问题（背景，讲故事）

打开真实路径为 `xxx` 的文件时，顶部面包屑显示为「专题 / xxx」——凭空多了一个「专题」前缀段。面包屑的职责是如实反映文件位置，多出的段会让用户误以为文件在某个"专题"目录下，破坏对路径信息的信任。

[证据] 用户观察："当前显示的是 专题/xxx，多了一个专题前缀。"

### 现状失败模式

- 现在：面包屑 = 「专题」+ 真实路径段；用户只能心里忽略第一段。
- 为什么不够好：与磁盘真实结构不符，误导定位。

## 成功标准（脊柱 Q4）

- 面包屑段数与内容 = 文件真实路径的层级段，多余前缀段：1 个 → 0 个。

## 验收标准（Given-When-Then）

### AC-1 — 无多余前缀

- **Given** 一个真实路径为 `a/b/c.md` 的文件
- **When** 用户打开它并查看顶部面包屑
- **Then** 面包屑逐段为 `a / b / c.md`，不含「专题」或任何真实路径之外的前缀段

### AC-2 — 各入口一致

- **Given** 同一文件分别从 workspace tree、专题列表等不同入口打开
- **When** 查看面包屑
- **Then** 均显示同一真实路径，与打开入口无关

## 三类边界（Won't）

- **不为哪些用户做**：无排除。
- **不在哪些场景出现**：不改面包屑的视觉样式与交互（点击跳转等维持现状）。
- **不解决哪些相关但不同的问题**：不重新设计"专题"概念在导航中的呈现——只修面包屑与真实路径不符这一点。
