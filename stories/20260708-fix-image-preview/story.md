# 修复：点击图片文件无法加载显示

> 一句话概括：**为浏览 workspace 的用户修复"点击 PNG 等图片文件后详情区无法正常显示图片"的缺陷**

## 用户故事（Connextra）

作为 **在 workspace tree 中浏览文件的用户**，
当我 **点击一个 PNG（或其他常见格式）图片文件**,
我希望 **详情区正常渲染出这张图片**，
以便 **不必离开应用去 Finder 里看图**。

## 真实用户问题（背景，讲故事）

用户在 workspace tree 点击 PNG 文件，详情区无法正常加载并显示图片（当前表现：加载失败/空白/错误态）。浏览是产品核心任务（docs/final-state.md），图片是 Agent 产出与知识资产的常见形态，此路径必须可用。

[证据] 用户实际操作复现："点击 png 图片，无法正常加载图片并显示出来"。

### 现状失败模式

- 现在：点击图片 → 无图可看；用户只能去文件系统里打开。
- 基线：图片预览成功率 0%。

## 成功标准（脊柱 Q4）

- 点击 workspace 中图片文件 → 详情区渲染成功率 0% → 100%（常见格式）。

## 验收标准（Given-When-Then）

### AC-1 — PNG 正常显示

- **Given** workspace 中存在一个有效的 PNG 文件
- **When** 用户在树中点击它
- **Then** 详情区完整渲染该图片，无错误提示、无空白

### AC-2 — 其他常见图片格式同样修复

- **Given** workspace 中存在 JPG / GIF / WebP / SVG 文件
- **When** 用户点击
- **Then** 同样正常渲染（同一根因应一并覆盖，修一处而非只修 PNG 路径）

### AC-3 — 损坏图片的可理解反馈

- **Given** 一个损坏/不完整的图片文件
- **When** 用户点击
- **Then** 显示明确的"无法预览"反馈而非无限加载或崩溃

## 三类边界（Won't）

- **不为哪些用户做**：无排除。
- **不在哪些场景出现**：不涉及 markdown 内嵌图片的渲染（若那也坏了另立故事）；不涉及图片编辑/标注。
- **不解决哪些相关但不同的问题**：不做缩放/旋转等图片查看器增强；不做视频等其他媒体类型预览。
