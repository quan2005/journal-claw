# 无法识别类型的文件：提示用户选择纯文本渲染

## 用户故事

作为 JournalClaw 用户（知识工作者），当我在文件树点开一个 App 不认识的文件类型（如 `.log`、`.conf`、`.jsonl`、无扩展名文件）时，我希望 App 提示我可以用纯文本方式直接查看，而不是只给一个"用系统应用打开"的死胡同。

## 背景与失败模式

[证据] `DetailView.tsx:1830-1864`：`other` 类型文件的详情面板只显示文件名 + "用系统应用打开"按钮。
失败模式：workspace 里大量 Agent 产物/配置/日志文件扩展名不在白名单（`fileKind.ts` 硬编码），用户想快速瞄一眼内容也被迫离开 App 跳到外部程序，与"高效浏览 + 沉浸阅读"的产品北极星冲突；现状规避方式是改扩展名或用 Finder 打开。

## 目标状态

- 未识别类型的详情面板给出两个选择："以纯文本查看"（App 内直接渲染）与"用系统应用打开"（保留现状）。
- 选择纯文本后，内容以与 `.txt` 文件一致的阅读体验展示。

## 验收标准

- **AC-1** Given 文件树中一个未识别类型的文件，When 点击选中它，Then 详情面板显示提示，含"以纯文本查看"与"用系统应用打开"两个操作，不自动加载内容。
- **AC-2** Given 该提示面板，When 点击"以纯文本查看"，Then 文件内容以纯文本形式在 App 内展示（与 .txt 一致的样式与查找能力）。
- **AC-3** Given 用户已对某文件选择纯文本查看，When 切走再切回该文件，Then 本次会话内直接以纯文本展示，不重复询问。
- **AC-4** Given 一个已识别类型的文件（md/html/图片等），When 点击它，Then 行为与现在完全一致，不出现该提示。

## 边界（Won't）

- 不为已识别的二进制类型（audio/docx/archive/pdf 等）提供纯文本入口——它们保持现有面板。
- 不做"记住我的选择"的持久化偏好（跨会话仍会再询问）。
- 不做编码检测/二进制内容嗅探的完善处理（乱码属可接受结果，用户可自行退回）。
- 不扩充 fileKind 扩展名白名单（那是另一个问题）。

## 交棒清单（转 design）

- 超大文件的加载上限与截断提示。
- 会话内记忆的存放位置（组件态/上下文）。
