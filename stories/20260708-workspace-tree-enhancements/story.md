# Workspace 文件树排序、图标与操作效率增强

> 一句话概括：**为 JournalClaw 桌面用户解决 Workspace（专题空间）文件树在条目变多后难排序、难辨认类型、必须切到 Finder 才能新建/改名的问题**

## 用户故事（Connextra）

作为 **JournalClaw 桌面版用户，在 Workspace（专题空间）面板管理自己的文件/文件夹树**，
当我 **专题下的文件夹和文件逐渐变多**，
我希望 **能自主控制显示顺序、一眼分辨文件类型、不离开应用就能新建/重命名/用键盘操作树**，
以便 **更快找到目标文件，减少心流被打断的次数（比如切到系统 Finder 操作完再切回来）**。

## 真实用户问题（背景，讲故事）

[证据] 当前 Workspace 面板（`apps/web/src/components/TreeSidebar.tsx`/`TopicTree.tsx`/`TreeItem.tsx`）截图显示一个专题下已有 9 个子文件夹 + 1 个 README，用户反馈希望"更加深入的优化专题空间的展示"。

### 现状失败模式

- **排序**：[证据] `useTopics.ts` 的 `listDir` 不做任何排序，条目按 daemon 返回的原始顺序展示（`useTopics.ts:6-7`），用户无法按名称/时间/类型重新组织，文件夹一多，想找的文件夹位置不固定、要来回扫视整个列表。
- **图标**：[证据] `TreeItem.tsx:110` 所有文件夹统一用同一个 `'folder'` 图标，不区分展开/折叠；文件类型图标（`FileTypeIcon.tsx`）覆盖面不全（缺 json/yaml/toml 等配置类），未覆盖类型一律落到 `other` 通用图标，用户扫视时无法快速区分"这是我常打开的脚本"还是"一份不认识的配置文件"。
- **操作效率**：[证据] 右键菜单（`TreeContextMenu.tsx`）目前只有 置顶/复制路径/编辑器打开/显示于访达/归档/删除，**没有新建文件、新建文件夹、重命名**——用户想改名或新建，必须切到系统 Finder 操作，打断当前工作流；树容器也没有键盘导航（无 `tabIndex`/方向键绑定），键盘操作用户无法脱离鼠标浏览/展开树；文件夹展开后如果没有子项，界面上没有任何反馈，容易被误认为卡住了；文件夹本身也不显示子项数量，无法一眼判断哪个文件夹内容多。

## 成功标准（脊柱 Q4）

### 用户行为变化

做完后，Workspace 用户会：

- 遇到条目多的专题时，主动切换排序策略整理视图，而不是放弃寻找、滚动硬找：**当前 0 次排序操作可用 → 4 种排序策略可选且跨会话记住上次选择**
- 通过图标形状而非记忆文件名来识别常见类型（md/pdf/图片/代码/配置）：**当前仅 ~6 种类型有区分图标 → 覆盖 md/pdf/docx/表格/csv/图片/代码/html/文本/压缩包/json/yaml/toml 共 12+ 类，且文件夹区分展开/折叠两态**
- 新建文件、文件夹、重命名不再需要切到系统 Finder：**当前 0 → 右键菜单直接支持**
- 键盘可完成"移动焦点 - 展开/折叠 - 打开"全部操作，不必依赖鼠标

⚠️ 假设依据：以上基于直觉（用户对当前树状态的直接反馈 + 团队对文件管理器通用交互的经验），无量化埋点验证计划，作为可用性改进直接上线观察后续反馈。

## 验收标准（Given-When-Then）

### AC-1 — 切换排序策略

- **Given** 我在 Workspace 面板的专题树中
- **When** 我点击排序入口并选择"名称 A-Z"/"名称 Z-A"/"最近修改"/"类型优先"其中一种
- **Then** 树内所有层级的子项立即按所选策略重新排列
- **And** 置顶（pinned）区域顺序不受此设置影响，始终保持原有的手动置顶顺序

### AC-2 — 排序策略持久化

- **Given** 我上次选择了某个排序策略（非默认）
- **When** 我关闭应用后重新打开
- **Then** Workspace 树仍按我上次选择的策略显示，而不是回到默认策略

### AC-3 — 按类型识别文件图标

- **Given** 专题文件夹下包含 md、pdf、图片、代码、json 等多种类型文件
- **When** 我查看文件树
- **Then** 每种类型显示彼此不同的图形符号图标（而非统一图标或纯文字缩写）
- **And** 此前未被特殊处理的类型（如 json/yaml/toml）也有各自专属图标，不再统一显示为通用兜底图标

### AC-4 — 文件夹展开态图标反馈

- **Given** 一个折叠状态的文件夹，显示"关闭"样式的文件夹图标
- **When** 我点击展开该文件夹
- **Then** 图标切换为"打开"样式的文件夹图标
- **And** 折叠回去后图标恢复为"关闭"样式

### AC-5 — 文件夹子项计数

- **Given** 一个包含若干直接子项（文件+子文件夹）的文件夹
- **When** 我查看该文件夹所在行
- **Then** 行尾显示该文件夹直接子项的数量

### AC-6 — 空文件夹提示

- **Given** 一个没有任何子项的文件夹
- **When** 我展开它
- **Then** 我能看到一行明确的"空文件夹"提示，而不是展开后空白一片

### AC-7 — 手动拖拽排序

- **Given** 我已将排序策略切换为"手动"
- **When** 我拖拽某个文件/文件夹到树内的新位置
- **Then** 该项移动到新位置，且下次打开应用时顺序保持
- **And** 当排序策略不是"手动"时，拖拽把手不出现，无法拖拽

### AC-8 — 右键新建文件/文件夹

- **Given** 我在树内某个文件夹上右键
- **When** 我选择"新建文件"或"新建文件夹"
- **Then** 树内出现一个待命名的新文件/文件夹，供我输入名称后创建成功

### AC-9 — 右键重命名

- **Given** 我在树内某个文件或文件夹上右键
- **When** 我选择"重命名"并输入新名称确认
- **Then** 该项在树内和底层文件系统中的名称同步更新为新名称

### AC-10 — 键盘导航

- **Given** 树容器已获得焦点
- **When** 我依次按 ↓/↑、→/←、Enter
- **Then** 焦点分别在同级/跨层级行间下移/上移、展开/折叠当前文件夹、打开当前文件或进入重命名/选中状态

## 三类边界（脊柱 Q5 · Won't · 输出闸必填）

- **不为哪些用户做**：不做"每个文件夹可各自独立设置排序策略"——只提供一个全局排序策略，理由：用户已确认接受全局单一策略，多套策略会显著增加数据模型与 UI 复杂度但当前无明确诉求。
- **不在哪些场景出现**：不做"树内搜索时自动展开+高亮命中项"——理由：现有搜索入口（🔍 图标）尚未接任何搜索逻辑，属于未来独立的搜索功能立项范畴，不应绑进本次树体验改动。
- **不解决哪些相关但不同的问题**：不做文件夹自定义图标/颜色（用户已确认只要类型细分，不要素材自定义）；不做多选/批量操作、剪切/粘贴、撤销历史——这些是更大的文件管理操作集，本次只聚焦排序/图标/新建/重命名/键盘导航这五类。
