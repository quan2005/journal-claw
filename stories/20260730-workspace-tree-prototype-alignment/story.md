# 工作空间文件树对齐参考原型

> 一句话概括：**为在工作空间中高频浏览多层文件的知识工作者，建立与参考原型一致、可快速扫读且不牺牲现有操作能力的文件树视觉层级。**

## 用户故事（Connextra）

作为 **在 JournalClaw 桌面端管理本地知识文件的知识工作者**，
当我 **展开多层目录、扫视文件类型并选择目标文件时**，
我希望 **目录、文件和当前选中项具有与参考原型一致的边距、缩进、图标、行距和层级引导**，
以便 **不用反复辨认错位的名称与控件，就能沿清晰层级快速定位并操作文件**。

## 真实用户问题（背景，讲故事）

[证据] 用户于 2026-07-30 提供一张工作空间文件树原型，并明确要求边距、图标、缩进等细节保持一致。

[证据] 原型 PNG 实际尺寸为 596×1100 px。按可见字号、34 CSS px 行节奏和图标尺度判断，它高概率是约 298×550 CSS px、DPR≈2 的侧栏截图；DPR 是推测，不作为产品行为契约，最终以等比例归一化后的视觉锚点验收。

[证据] 当前工作空间树同时存在顶部 `Workspace` 工具栏、`工作空间` 分组标题和文件树；参考原型顶部只显示“个人空间”。当前搜索按钮没有实际搜索行为，用户已于 2026-07-30 明确要求删除该未实现入口；随后在 HTML mockup 中选择方案 B，要求在“个人空间”标题行始终显示排序按钮，以可发现性优先。用户同时确认选中态必须继续使用信号橙，并要求整体注意圆角、保持圆润。当前顶层、一级、二级条目的缩进步长与同级目录/文件名称列也未统一，而原型中的名称列按层级严格对齐。

[证据] 历史 story 已分别验收排序、文件类型图标、紧凑目录、目录无图标、悬浮态、选择和键盘导航，但没有任何 approved / in_progress story 覆盖本次原型级视觉对齐。`stories/20260730-ui-surface-cleanup/story.md` 只处理主界面其他冗余入口，不覆盖文件树。

[证据] 用户于 2026-07-31 在最终视觉验收前追加三项反馈：目录后不显示统计数字；修复右键菜单中删除无效；重新选择文件 icon 主题。用户在可视化对比中明确选择 **B · Glyph Tile**，并确认按“圆润色块 + 简洁 glyph + 语义色”方向落地。

[证据] 标题区方案 B 的可视稿只保留“个人空间 + 常显排序”，不包含无行为的 `View layout`；用户选择“方案B”后再次明确“没问题，落地吧”。因此布局空壳入口与搜索空壳入口一并移除属于已确认视觉结果，不是额外功能裁剪。

[证据] 用户于 2026-08-01 对最终 596×1100 浅色、暗色与原型叠加证据明确回复“确认”，完成主观视觉验收；此前第二轮独立验收已确认 AC-1～AC-11 技术门禁通过。

### 现状失败模式

- 用户现在只能在既有文件树中依靠文字和展开箭头辨认层级，并容忍同级目录名与文件名不在同一文字列。
- 当前每级缩进、行高、图标占位和选中背景各自形成视觉节奏；在连续浏览两级以上目录时，名称起点与操作区变化增加横向扫视成本。
- 当前选中项没有形成参考原型中横贯侧栏的完整胶囊，尾部操作顺序与原型也不一致。
- 参考原型使用中性灰选中背景，但用户已确认 JournalClaw 的选中态继续使用信号橙；本次只复刻完整胶囊的圆润几何，不复制原型的灰色。
- 目录名后的子项计数与用户要的克制扫读界面冲突，在窄侧栏中还会与行尾操作争抢空间。
- 工作空间树已经浏览整个 workspace 根目录，但右键删除仍使用旧 `topics/` 路径；在纯 Web 环境中，删除又会因缺少原生确认框而直接中止，因此用户看到的结果是“点击删除没有反应”。

## 成功标准（脊柱 Q4）

### 用户行为变化

做完后，目标知识工作者会：

- 在固定的根目录、一级目录、二级目录样例中，看到 **3 个层级的名称列、引导线和展开箭头稳定对齐**，每级视觉缩进均为 **10 CSS px，关键锚点误差不超过 2 CSS px**。
- 浏览连续文件行时，行中心间距稳定为 **34 CSS px**；选中项形成与行高一致的完整信号橙胶囊，关键几何误差不超过 **2 CSS px**。
- 继续完成排序、展开/折叠、文件选择、`@` 引用、更多菜单、右键菜单和键盘导航：上述 **7 类既有能力保留率为 100%**；未实现的搜索入口从 **1 个降为 0 个**。
- 在浅色与暗色主题下都能辨认默认、悬浮、选中和键盘聚焦状态：**4 类状态均可用**，无文字或图标被截断、遮挡。
- 选中项、文件图标轮廓和树内交互控件保持统一、圆润的视觉语言：**3 类圆角元素均无突兀直角或彼此冲突的圆角节奏**。
- 在主树和置顶树中查看目录时，目录名后的可见子项计数从当前存在降为 **0 个**，名称列和行尾操作不因计数变化。
- 在纯 Web 和 Electron 两种环境中，对工作空间文件或目录确认删除后，**2 类对象 × 2 种宿主环境的删除任务成功率均为 100%**；取消确认时不发生删除。

⚠️ 假设依据：视觉方向来自用户明确提供的原型与文字要求；几何目标来自原型测量。对扫读效率的提升属于直觉假设，将通过等比例截图叠加和用户走查验证。

## 验收标准（Given-When-Then）

### AC-1 — 根级标题与起始边距

- **Given** 用户打开工作空间文件树的浅色主题基准场景
- **When** 文件树完成渲染
- **Then** 顶部显示“个人空间”标题与始终可见的排序按钮，不再显示 `Workspace`、无行为的搜索/布局按钮或额外的“工作空间”分组标题
- **And** 标题、根级箭头、根级文件图标与文字的起始位置和参考原型等比例对齐，误差不超过 2 CSS px

### AC-2 — 三层目录缩进与引导线

- **Given** 文件树包含展开的根目录、一级目录和二级文件
- **When** 用户查看该树
- **Then** 根级、一级、二级名称分别落在稳定的文字列
- **And** 相邻层级的缩进增量均为 10 CSS px，竖向引导线与对应层级对齐，关键锚点误差不超过 2 CSS px

### AC-3 — 同级目录与文件名称对齐

- **Given** 同一层级同时存在目录和文件
- **When** 用户扫视该层级
- **Then** 目录名称和文件名称从同一文字列开始
- **And** 目录仍以展开箭头表达类型，文件仍显示对应的文件类型图标

### AC-4 — 文件类型图标

- **Given** 工作空间中同时存在 Markdown、HTML 和其他已支持类型文件
- **When** 用户查看文件树
- **Then** 每个文件显示用户选定的 Glyph Tile 主题：圆润色块承载简洁 glyph，Markdown、HTML、图片、PDF 与其他已支持类型保持稳定语义区分
- **And** 新图标主题不改变同级名称列、每级 10 CSS px 缩进和 34 CSS px 行节奏；在信号橙选中背景上仍清晰可辨

### AC-5 — 行高与选中胶囊

- **Given** 用户在连续文件行中选择一个文件
- **When** 选中状态出现
- **Then** 各行中心间距为 34 CSS px，误差不超过 2 CSS px
- **And** 选中背景使用信号橙，形成横贯可用侧栏宽度、与行高一致的完整圆润胶囊，不显示额外的左侧选中条

### AC-6 — 尾部操作

- **Given** 文件行处于选中、悬浮或键盘聚焦状态
- **When** 尾部操作出现
- **Then** 用户按参考原型的顺序看到“…”和“@”
- **And** 两个操作均可点击；未选中、未悬浮且无键盘焦点的行不显示尾部操作

### AC-7 — 目录展开与折叠

- **Given** 文件树包含有子项的展开目录和折叠目录
- **When** 用户切换任一目录状态
- **Then** 箭头方向、子项显隐、引导线长度和后续条目位置同步更新
- **And** 展开或折叠不会改变同级名称列与每级 10 CSS px 的缩进节奏

### AC-8 — 排序与键盘操作不回归

- **Given** 用户进入完成视觉对齐后的工作空间文件树
- **When** 用户依次使用排序、方向键、Enter、右键菜单、`@` 和更多菜单
- **Then** 这些既有操作都能继续完成原有任务，且页面不再显示无行为的搜索入口
- **And** 键盘焦点始终有符合设计规范的可见聚焦环

### AC-9 — 暗色主题

- **Given** 用户切换到暗色主题
- **When** 查看默认、悬浮、选中和键盘聚焦状态
- **Then** 文件树保持与浅色主题一致的几何层级和操作能力
- **And** 文字、箭头、引导线、图标和操作按钮均清晰可辨

### AC-10 — 目录不显示统计数字

- **Given** 工作空间树中的目录包含一个或多个子项
- **When** 用户查看该目录的默认、悬浮、选中和聚焦状态
- **Then** 目录名后不显示子项数字
- **And** 行尾空间仅保留已批准的拖拽把手和“…”、“@”操作，名称列不发生偏移

### AC-11 — 右键删除文件与目录

- **Given** 用户在纯 Web 或 Electron 中右键一个工作空间文件或目录
- **When** 用户选择删除，并在确认框中选择确认或取消
- **Then** 确认时目标从工作空间文件树中消失，文件树与置顶状态同步刷新
- **And** 取消时目标保留且文件树不发生变化

## 三类边界（脊柱 Q5 · Won't · 输出闸必填）

- **不为哪些用户做**：不为只调用 daemon/API、看不到图形界面的集成用户改变任何行为；本故事只服务桌面端工作空间文件树使用者。
- **不在哪些场景出现**：不改日志时间线、身份列表、详情面板、设置页、聊天面板或工作空间之外的树/列表样式；不把桌面侧栏原型扩展为移动端触控设计。
- **不解决哪些相关但不同的问题**：不实现新的文件搜索或布局切换能力；除删除方案 B 已确认的无行为搜索/布局入口和恢复工作空间右键删除外，不新增或删除排序、置顶、紧凑目录、其他文件 CRUD、右键菜单、拖拽排序、键盘导航和文件类型识别能力；plain Web 标准确认只用于工作空间文件/目录删除，不改变详情页、日志、身份或其他 `hostAsk` 调用；不改 daemon、文件系统、ChangeSet、权限、持久化或运行时协议；不新增第三方图标或样式依赖，Glyph Tile 仅用于工作空间文件树。
