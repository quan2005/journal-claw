1 四大核心文件
scripts/server.cjs
HTTP 服务器 + WebSocket + 文件监控。手写 RFC 6455 帧编解码，零 npm 依赖。自动包裹 content fragment 到 frame template。
scripts/frame-template.html
页面外壳：CSS 变量主题系统（Apple SF 风格）、dark/light 自适应、网格布局、线框组件库。 注释是 AI 内容的注入点。
scripts/helper.js
客户端脚本（注入到每页）。WebSocket 连接管理、点击事件捕获、toggleSelect() 选择 UI、reload 响应。
visual-companion.md
AI 操作指南。定义何时用浏览器 vs 终端、CSS 类速查、启动命令、事件格式、文件命名规范。
2 Content Fragment — 核心设计决策
server.cjs 通过检测第一行是否以 <!DOCTYPE 或 <html 开头来判断：Fragment → 自动包裹 frame；Full doc → 只注入 helper.js。
默认写 fragment，让 AI 无需关心 CSS 和页面结构。

3 AI 工作循环（每次交互一轮）
1
检查服务器存活
Read state_dir/server-info，若不存在（或 server-stopped 文件存在）则重启。服务器 30 分钟无活动自动退出。
2
Write HTML fragment → screen_dir
语义化文件名（layout.html, style-v2.html），绝不复用文件名。只用 Write 工具，不用 cat/heredoc。
3
fs.watch 检测新文件 → 清空旧 events → 广播 reload
server.cjs 的 knownFiles Set 区分"新文件"和"覆盖"。新文件才清 events、log screen-added。WebSocket broadcast {type:'reload'}。
4
浏览器自动刷新，用户查看 + 点击选项
helper.js 的 toggleSelect() 处理单选/多选、更新底部 indicator bar。每次点击通过 WebSocket 发 {type:'click', choice, text, timestamp}。
5
server.cjs 收到 WebSocket 消息 → append 写入 events 文件
一行一个 JSON：{"type":"click","choice":"a","text":"...","timestamp":1706000101}
6
AI 下一轮：Read events 文件 + 用户终端文字 → 决定下一步
合并双通道反馈。events 可揭示用户犹豫路径（多次点击才确定）。若 events 不存在 → 用户未交互浏览器。
7
迭代 或 push waiting.html 切回终端模式
当前问题未定 → 写新版本（layout-v2.html）。当前问题已定 → push waiting screen 清屏，继续终端文字讨论。
4 AI 可用的 CSS 组件库速查
所有样式预定义在 frame-template.html 中。AI 只需记住这些 class 组合，无需手写 CSS。
HTML 模式视觉效果用途
.options > .option > .letter + .content 竖排 A/B/C 卡片，hover 蓝边，选中蓝底，字母徽章变色 文字选项选择（单选默认，data-multiselect 变多选）
.cards > .card > .card-image + .card-body 响应式网格（minmax 280px），卡片 hover 上浮 + 阴影 视觉设计/线框图对比选择
.mockup > .mockup-header + .mockup-body 模拟窗口外观，灰底 header 条 + 白色内容区 展示 UI 设计、页面布局线框图
.split > .mockup × 2 1:1 并排网格（700px 以下堆叠） 并排对比两个方案
.pros-cons > .pros + .cons 1:1 网格，绿色标题 "Pros" / 红色 "Cons" 方案优劣对比
.mock-nav / .mock-sidebar / .mock-content 蓝色导航条 / 灰色侧栏 / 白色内容区 页面骨架线框图
.mock-button / .mock-input 蓝色按钮 / 圆角输入框 线框图中的控件
.placeholder 虚线边框 + 居中文字 标注未设计/占位区域
h2 / h3 / .subtitle / .section / .label 统一字号字重层级 排版：标题、副标题、区块分隔、小标签
5 关键设计决策与约束
A
Fragment 优先，极少用 full document
降低 AI 写出破损 HTML 的概率。全页控制仅用于需要脱离 frame 框架的特殊场景。
B
文件名即状态：不复用，语义化，v2/v3 版本迭代
server.cjs 通过 knownFiles Set 跟踪所有历史文件。新文件名 → 清空旧 events 数据 → 新屏幕独立的交互上下文。
C
双通道反馈：events（结构化点击流）+ 终端文字
events 存储完整的点击序列（含犹豫路径），终端文字提供非结构化补充。AI 合并两者做判断。
D
Server 生命周期绑定 session
30 分钟闲置 → 自杀。主进程退出（kill -0 检查 owner PID）→ 自杀。写入 server-stopped 哨兵文件供 AI 检测。
E
waiting screen 清屏协议
当下一轮问题不需要浏览器时，push 一个极简 waiting.html 防止用户盯着已解决的选择界面。
